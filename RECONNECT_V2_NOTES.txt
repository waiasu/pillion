Reconnect v2 test build

Scope:
- Keep existing FPS minimum = 1 fps.
- Keep the reconnect-wait behavior from diagnostic v1.
- Filter Bluetooth ACL events to YCCU/CCU devices.
- On YCCU/CCU ACTION_ACL_CONNECTED while reconnectWait=true:
  1. wait 1500 ms for the base Bluetooth link/CCU to settle
  2. create a fresh RfcommByteChannel
  3. create a fresh MirrorEngine/NaviLite session
  4. reuse the already-alive ScreenSource/helper/VD infrastructure (do not restart MediaProjection)
  5. leave reconnectWait only after actual Streaming state is reached
- If reconnect fails while ACL remains connected, stay alive in STATUS and retry after 5000 ms.
- Notification Stop remains the explicit full shutdown path.

Not included yet:
- waking the phone after reconnect
- forcing/promoting VD after reconnect
- recreating MediaProjection or helper

Useful log markers:
reconnect-v2: BT ACL_CONNECTED
reconnect-v2: scheduling rebuild
reconnect-v2: attempt=N rebuilding RFCOMM + NaviLite session
session: reusing existing screen capture
rfcomm: connected to ...
session: handshake
session: streaming
reconnect-v2: session stable; leaving reconnect wait
reconnect-v2: reconnect attempt=N failed
